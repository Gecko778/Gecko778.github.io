Conversation Protocol

<|im_start|>, <|im_sep|>, <|im_end|> These are the special tokens are introduced and interspersed with text so that they get the model to learn where is the start, end, sep.

The conversation which we think is a structured object end up being turned via some encoding into one dimensional sequence of tokens. Because it’s one dimensional sequence, it means we can apply this as we apply before in pretraining.

Conversation Datasets: DISPEL the magic of talking to AI

When you go to ChatGPT and you give it a question and you hit enter. What is coming back is kind of like statistically aligned with what’s happening in the trainging set. In these training sets, they really have a seed in human following labeling instructions.

So what are you actually talking to ChatGPT or how should you think about it? It’s not coming from some “magical” AI like roughly speaking. It’s coming from something that is statistically imitating human labelers which come from labeling instructions written by these companies. It’s almost as if you’re asking human labeler. Imagine that the answer that is given to you from ChatGPT is some kind of a simulation of a human labeler.

The human labeler is the highly skilled experts which companies hire.

But remember, the model already has a ton of knowledge from its pre-training on the internet. The pre-training knowledge that has then combined with the post-training data set that results in this kind of an imitation.

Mitigation #2 Give model an opportunity

If your friend asks you a question and you don’t know, what would you do? You could do some search and then tell me what answer is. We can do the exact same thing with these models.

Think of the knowledge inside of the neural networks inside its billions of parameters. Think of that as a vague recollection of the things that the model has seen during the training or pre-training stages long time ago. From the perspective of human, think of that as something you read a month ago. If you keep reading something then you will remember it and the model remembers that. But if it’s something rare then you probably don’t hava a good recollections of that information. You and I just look it up. When you look it up, what you’re doning is basically refreshing your working memory.

Models need tokens to think

e.g. 1 Try to do all the compstation in a single token

The answer is $3. This is because 2 oranges at $2 are $4 total. So the 3 apples cost $9, and therefore each apple is 9/3=$3.

e.g. 2

The total cost of the oranges is $4. 13-4=9, the cost of the 3 apples is $9. 9/3=3, so each apple costs $3. The answer is $3.

There’s a finite amount of computation that happens here for every single token. You should think of this as a very small amount of comptation and this amount of computation is almost roughly fixed for every single token in this sequence. The more tokens you feed in, the more expensive this forward pass will be.

They are working on one dimensional sequence from left to right.

The model basically do arbitrary computation in a single forward pass to get a single token. So We have to distribute our reasoning and our computeration across many tokens because every single token is only spending a finite amount of computation on it. We can’t have or expect too much computation out of the model in any single individual token because there’s only so much computation that happens per token roughly fixed amount of computation here.

e.g. 1 Cram all of the computation of this problem into one single token. It has to emit the correct answer 3.

It’s already in the token window so it’s not actually being calculated.

So if you are answering the question directly and immediately, you are training the model to try to basically guess the answer in a single token. That is not gonna work because the finite amount of computation happens per token.

left to right, slowly == not that expensive

We are teaching the model to spread out its reasoning and comptation over the tokens.

Models can’t count

Models are not good with spelling. Models see tokens(text chunks), not individual letters.

If you ask GPT: Print back the following string. But only print every 3rd character, start with the first one.

It would be wrong answer.

Models sometimes fall short in super simple problems like this: “What is bigger 9.11 or 9.9?”

Conclusion

So far, the difference between Stage 1 pre-training and Stage 2 Post-training is the data set.

Pre-training’s dataset is Internet documents.

Post-training create and curate a very nice data set of conversations. So we want millions of conversations on all kinds of diverse topics between a human and an assistant. And these conversations are created by humans. So humans write prompts and ideal responses based on labeling documents. Currently language models {https://atlas.nomic.ai/} can help us create these data sets.

Then we get a SFT model, an assistant, trained by Supervised Finetuning

Post-training: Reinforcement Learning

Just like you go to school, we let “models go to school“.

Exposition: background knowledge, like pre-training

Problems and worked Solutions: Supervised fine-tuning, imitation of experts, how they solve the problems

Practice problems: reinforcement learning, Given the problem description, not the solutions, but given the final answer.

We train them very similar to how we train children.

Read all the textbooks at the same time.

First, pre-training: Read all the exposition to build a knowledge base -> base model

Second, sft-stage: Look at all the fixed solutions from human experts across all the textbooks -> sft model imitate experts.

Last, Reinforcement Learning: Across all the textbooks, we only do the practice problems.

Deepseek R1 brings RL back

The previous two stages are very standard, all the different llm providers. But the last stage is not standard yet.

RLHF: Learning in underifiable domains

The domains that are harder to score our different solutions to this problem.

RLHF approach, involve humans just a little bit, then train a whole separate neural network that we call reward model which can imitate human scores. We ask humans to order instead of giving score because order is much easier than giving precise scores. Then compare the order from human and reward model, calculate the loss between these two order which is accessible by some kind of mathematical equations.

reward model is gameable. 滥用

There are two main stages we talked above. First the training stage where we tune the parameters of the model to perform the task well. Once we get the parameters, we fix them and then we deploy the model for inference. From there the model is fixed, it doesn’t change anymore. It doesn’t learn from all the stuff that it has done in test time. It’s fixed number of parameters. The only thing that is changing is now the token inside the context windows.

So the only type of learning or test time learning the model has access to is the in context learning of its dynamically adjustable context window depending on what it is doing at test.

Summary

How do we see the output of ChatGPT?

The neural network simulation of data labeler at openai following the labeling instructions of OpenAI.

As if I gave a query to a data labeler of openai and the data labeler first reads all of the labeling instructions from openai then spend 2 hours writing up the ideal assistant response to this query and give it to me. But I don’t have to wait 2 hours so what we’re getting here is a neural network simulation of that process. We have to keep in mind that what’s easy for these neural networks are different from what’s easy or difficult for humans.

GPT4o doesn’t do reinforcement learning, it does do RLHF. But RLHF is not RL, there’s no time in there. It’s just a little bit of fine-tuning.
